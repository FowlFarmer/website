# On Learning

*April 20, 2026*

Learning something new has a particular shape to it. There's an early phase of excitement — everything is novel, progress feels fast. Then comes the middle, which is murkier. You know enough to see how much you don't know.

I've been thinking about that middle phase a lot lately.

## The illusion of early progress

When you start learning anything — a language, an instrument, a framework — the first 10% comes quickly. You're building on a lifetime of adjacent knowledge. You know what a function is. You've seen syntax before. Pattern-matching does most of the work.

This is dangerous, because it feels like competence. It isn't. It's orientation.

## The useful friction

The middle phase is where the actual learning happens, but it doesn't feel that way. Everything slows down. You hit concepts that don't map cleanly onto anything you already know. You have to build new mental models from scratch.

This friction is the point. Trying to skip it — by watching another tutorial, reading another overview — is just delaying it.

The only way through the middle is to build things that break, read errors carefully, and sit with confusion long enough that it resolves into understanding.

## What I try to do

- **Build something stupid.** The project doesn't have to be good. It has to be real enough that breaking it matters.
- **Read primary sources.** Docs over tutorials. Papers over blog posts. The original is usually clearer than the summary.
- **Explain it out loud.** If I can't explain a concept to an imaginary skeptic, I don't understand it yet.

That's about all I've figured out. The rest is just showing up.
